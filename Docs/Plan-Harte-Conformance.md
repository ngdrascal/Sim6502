# SingleStepTests wdc65c02 conformance

Status: done. Every opcode with vectors matches them cycle for cycle, apart from the permanent
opt-outs below. This file records the sources rule, the remaining deviations, and what changed.

## Sources rule

Follow the SingleStepTests 65x02 `wdc65c02/v1` vectors (Tom Harte; https://github.com/SingleStepTests/65x02)
over MAME. If the vectors disagree with WDC documentation (`Docs/DataSheets/w65c02s.pdf`), stop and ask.
The W65C816S datasheet is not used. None of these sources is a hardware capture.

## Conformance test

`W65C02S.Engine.Tests/HarteConformanceTests.cs` runs a vendored subset of the vectors
(`W65C02S.Engine.Tests/Harte/`, about 4,500 cases, regenerated by `scripts/HarteSubset.cs`). It has one
theory row per opcode and checks:
- every cycle's address, data and read/write
- the cycle count
- final PC/A/X/Y/S, and P with bits 4 and 5 masked
- the final RAM

Known deviations are in its opt-out list: one entry per opcode, with an optional predicate on the
initial state. An opted-out opcode whose cases all pass fails the test, so remove its entry.

Permanent opt-outs:
- `5C` NOP: the WDC datasheet Table 7-1 gives 8 cycles, and the vectors give 4. The engine keeps 8.
- `69` / `E9` ADC/SBC immediate, decimal mode only: the vectors add a cycle that reads `$007F` (69)
  or `$0000` (E9) in every case. No other source backs it, so it looks like an artifact of the
  emulator that generated the vectors. The engine's cycle count already matches.
- `CB` (WAI) and `DB` (STP): upstream has no cases. Their bus activity is unchanged.

## What changed

Notation: PC = opcode address, c0 = opcode fetch.

| Group | Opcodes | Fix |
|-------|---------|-----|
| zero page pointer wrap | every (zp), (zp,X), (zp),Y opcode | pointer at `$FF` takes its high byte from `$00` (`InstBase.FetchEA2HighIndirectZp`) |
| JMP (abs) | 6C | 6 cycles; c5 re-reads pointer + 1 |
| ADC/SBC (zp),Y | 71 F1 | decimal mode with a page cross: 7 cycles |
| zp,X / zp,Y / (zp,X) | 15 16 34 35 36 54 55 56 74 75 76 94 95 96 B4 B5 B6 D4 D5 D6 F4 F5 F6; 01 21 41 61 81 A1 C1 E1 | c2 reads the zp base (`InstBase.IndexZpWithX` / `IndexZpWithY`) |
| abs,X / abs,Y / (zp),Y reads | 19 1D 39 3C 3D 59 5D 79 7D B9 BC BD BE D9 DD F9 FD; 11 31 51 71 B1 D1 F1 | page cross: the indexing cycle reads the last instruction byte, then EA (`InstBase.IndexEffAddr`); WDC Table 7-1 agrees |
| STA (zp),Y | 91 | c4 reads PC+1 |
| implied / accumulator | 0A 1A 2A 3A 4A 6A 18 38 58 78 88 8A 98 9A A8 AA B8 BA C8 CA D8 E8 EA F8 | c1 reads PC+1 |
| pulls | 28 68 7A FA | c2 reads the stack at S (before the increment) |
| RTS | 60 | c1 PC+1, c2 stack at S, c5 the pulled address (before +1) |
| RTI | 40 | c1 PC+1, c2 stack at S |
| JSR | 20 | c2 dummy read of the stack at S, c3/c4 push, c5 reads the high operand at PC+2 (was a second stack write) |
| JMP (abs,X) | 7C | c3 re-reads PC+1 (was PC+2) |

Benchmark cycle totals after the 6C change: Dormann 96,561,325, 65C02 extended 66,907,085, BCD
64,573,739 (unchanged).

Unit tests: `ZeroPagePointerWrapTests`, `IndirectYDecimalTests`, `IndexedBusActivityTests`,
`ImpliedStackBusActivityTests`, `ControlTests` (JMP (abs), JMP (abs,X), JSR).
